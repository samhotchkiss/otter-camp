Core Domains

Five Domain Boundaries

Each domain owns its data, rules, and events. Cross-domain communication happens through well-defined interfaces.

Chat

Owns sessions, messages, and participant state. The primary interface where humans talk to agents and agents take action.

Session Message Participant @mention trigger cycle_id

Project

Owns tasks, flow progression, and approvals. Tasks are created through conversation and persist until resolved.

Project ProjectTask FlowTemplate FlowNode FlowNodeExecution

Agent

Owns identity, lifecycle, and capability policy. Each agent is an expert in their domain with strong defaults.

Agent HumanUser Organization Skill ToolExecution

Memory

Owns extraction, retrieval, and retention. Background infrastructure with a conversational interface via @mention.

MemoryItem Extraction Scoring Retrieval Retention

Model

Owns provider abstraction, routing, and cost policy. A gateway layer that adapts to multiple inference providers.

ModelProfile Provider Adapter Routing Policy Cost Policy

Design Philosophy

Product Principles

Opinionated, Not a Blank Canvas

Agents propose the right approach based on context. Defaults are good enough that most users just say "yeah, go." Override is possible, but the happy path is the default path.

Chat Is the Primary Interface

The human talks to agents; agents take action. UI surfaces are for viewing and reviewing -- not for direct manipulation of system objects. Everything happens through conversation.

Progressive Disclosure

Show status at a glance, let the user drill in for detail. Never overwhelm with information that is not needed at the current level of zoom.

Agents Have Strong Defaults

When the PM designs a flow, they recommend the right one. When the PM scopes a task, they produce something ready to execute. Each agent is an expert in their domain and acts like it.

Blocked Progress Creates Tasks

When something requires action to keep a project moving, the system creates a task assigned to the responsible party. Notifications can be missed. Tasks persist until resolved.

Infrastructure

Storage and Eventing

PostgreSQL

  • All transactional entities (orgs, users, agents, sessions, tasks)
  • Durable event log table for replay and debugging
  • Domain events emitted on create/update transitions

Object Store

  • Large artifacts: session exports, screenshots, logs, files
  • Optional local filesystem mirror for single-node self-hosting
  • Decoupled from transactional path for performance

Eventing Model

  • Domain events on entity state transitions
  • Durable log for replay, debugging, and audit
  • Realtime fanout to subscribed clients via WebSocket / SSE
