Chat System

Chat is the primary interface for all human-agent and agent-agent interaction. Everything flows through chat -- commands, collaboration, autonomous work, and oversight.

Session Scoping
Three Scope Levels
Every chat session has exactly one scope. The scope determines context injection, agent availability, and available actions. One persistent session per scope -- no ambiguity.
O

Org

General-purpose conversations not tied to a project or task. Brainstorming with Frank, hiring via Lori, org-wide queries to Ellie.

Session: one persistent ("General")
Default responder: Frank
Agents: starter trio + org-level staff
Context: org memory, project summaries
→
P

Project

Conversations about a project as a whole -- blocker triage, progress reviews, staffing decisions, quick PM questions.

Session: one persistent per project
Default responder: project PM
Agents: trio + project staff + temps
Context: project + org memory, task summaries
→
T

Task

Conversations about a specific unit of work -- requirements, deliverables review, feedback, and resolving blockers.

Session: one sync + per-node async work logs
Default responder: PM / task lead
Agents: PM + task agents + Ellie
Context: task files, decisions, criteria + project + org
Session Modes
Sync vs Async
Sessions operate in one of two modes, determining context assembly strategy and latency expectations. Same core turn loop, different optimization priorities.
Synchronous

Human Present

Active human participation -- chatting with Frank, reviewing work, making decisions. Latency matters. Context is pre-assembled for speed.

  • Identity/personality: pre-loaded, always in prompt
  • Memory: Ellie injects top-k results passively per turn
  • Scope context: pre-assembled, re-injected every turn
  • Token budget: tight -- curated context
  • Default for: org and project sessions
Asynchronous

Autonomous Agent Work

Agent executing a task autonomously. Human is not waiting. Quality and thoroughness matter more than speed.

  • Identity/personality: pre-loaded, always in prompt
  • Memory: agent actively queries Ellie across turns
  • Scope context: injected once, agent discovers via tools
  • Token budget: relaxed -- many turns, context resets between steps
  • Default for: task-scoped flow node sessions
Multi-Party Sequencing
Turn Cycle
When a human sends a message, the system runs an atomic turn cycle through four phases: responder turn, agent-to-agent @mentions, listener eval, and interjection turns. The cycle completes fully before the next human message is processed.

Agent Execution
Core Turn Loop
The tool-call loop IS the agentic loop. One loop, two entry points (sync via human message, async via system kick). The agent reasons and acts through tool calls until it produces a final text response with no tool calls. Two tool tiers route execution appropriately.

Message Model
Rich Content Blocks
Messages use structured content blocks stored as jsonb, not plain text. Five roles (human, agent, system, tool_call, tool_result) with five block types for human-facing messages. Append-only with strict state transitions.

Prompt Assembly
7-Layer Context Pipeline
Run once at the start of each turn. Within the tool loop, each iteration appends tool calls and results -- the full pipeline is not re-run. Only Layer 6 grows during a turn. Progressive summarization manages history as sessions grow.
1

Agent Identity

Personality, role, behavioral guidelines. Pre-loaded, always present. Defines who the agent is.
set once
2

Policies and Constraints

Permission boundaries, tool policies (allow/deny/draft_review), budget limits. Agent knows what it can and cannot do.
set once
3

Scope Context

Task files, acceptance criteria, project state, decisions. Sync: re-injected every turn. Async: first turn only, agent discovers via tools.
set once
4

Skills

Agent-specific skills, capabilities, and specialized instructions relevant to the current scope.
set once
5

Memory (Ellie Passive)

Top-k relevant memories injected automatically per turn. Semantic retrieval based on scope and conversation content. No explicit invocation needed.
injected once
6

Conversation History

Recent turns in full + summaries of older turns. Progressive summarization keeps this within budget. The only layer that grows within a turn.
grows during turn
7

Tool Descriptions

Available tools with signatures, descriptions, and usage patterns. Tier 1 (read-only, chat-layer) and Tier 2 (mutations, control-plane) tools listed.
set once
Database Schema
6 Core Tables
PostgreSQL is the source of truth. Messages are append-only. Artifacts in object storage. Supporting tables include chat_read_cursor for unread tracking and chat_message_reaction for bidirectional sentiment signals.
chat_session
One session per scope. Carries sync/async mode, org binding, and a monotonic message sequence counter.
  • scope_typeorg | project | task
  • scope_iduuid (polymorphic FK)
  • modesync | async
  • statusactive | closed
  • message_seqint (atomic counter)
  • titletext (nullable, scope name fallback)
chat_participant
Human or agent membership in a session, with role and granular permissions. Append-only -- left_at marks departure.
  • participant_typehuman | agent
  • roledefault_responder | participant | listener
  • permissionstext[] (read, write, mention...)
  • joined_at / left_attimestamptz
chat_turn
Groups messages into complete cycles. Tracks trigger type, stop conditions, token usage, and duration. cycle_id links all turns from one human message.
  • cycle_iduuid (groups turns per human msg)
  • triggerhuman_message | system_kick | agent_mention | interjection | continuation
  • statusin_progress | completed | failed | stopped
  • stop_reasonmax_tool_calls | max_duration | user_cancelled | ...
  • tool_call_countint
  • input_tokens / output_tokensint
chat_message
One row per logical unit. Append-only with strict state transitions. Content varies by role -- rich blocks for human/agent, structured data for tool protocol.
  • rolehuman | agent | system | tool_call | tool_result
  • contentjsonb (blocks or tool data)
  • statepending | streaming | final | failed | redacted
  • sequenceint (per-session monotonic)
  • ephemeralboolean (purged by daily cleanup)
chat_artifact
Files, screenshots, logs in object storage (S3-compatible). Referenced from message content blocks. Session denormalized for efficient queries.
  • nametext
  • content_typetext (MIME type)
  • size_bytesbigint
  • storage_pathtext (object store location)
chat_summary
Progressive summarization for context management. Covers message ranges, replaces full content in the context window. Immutable -- newer summaries take precedence.
  • from_sequence / to_sequenceint (message range)
  • contenttext (summary text)
  • model_idtext (Haiku-tier)
  • token_countint (budget tracking)
