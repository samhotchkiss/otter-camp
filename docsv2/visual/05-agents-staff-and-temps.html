OtterCamp V2 — Spec 05

Agents: Staff & Temps

"Accumulated judgment vs. fixed rubric."

Agents are the workforce of OtterCamp. Every meaningful action — planning, coding, reviewing, triaging — is performed by an agent. The human directs and decides. Agents do the work. Two classes, one principle: the dividing line is whether the role needs persistent identity and cross-project memory.

Two Agent Classes

The distinction is about durability and identity, not capability. Staff agents persist, accumulate cross-project memory, and develop working relationships. Temp agents are the project workforce — always project-assigned, they do the work and do not chat with the human.

Staff Agents

Roles where persistent identity and cross-project memory matter
  • Durable identity — name, personality, role, and institutional knowledge persist indefinitely
  • Cross-project memory — knowledge gained in Project A informs decisions in Project B. The key differentiator from temps.
  • Reusable — assigned to multiple projects simultaneously with different roles
  • Memory-building — Ellie captures memories about and from staff agents. They develop institutional knowledge over time.
  • Org or project scoped — org-level agents available everywhere; project-level agents primarily associated with specific projects
  • Lifecycle — draft → active → paused → retired (human approval at draft)
  • Private memory — available for complex roles (PMs, Frank, Lori, Ellie). Working notes carry forward across every session and project.

Best for

PMs (always staff), org-level coordinators (Frank, Lori, Ellie), policy/content reviewers whose value comes from accumulated judgment, cross-project specialists (DevOps, database architects).

Temp Agents

The project workforce — always project-assigned, do the work, don't chat with the human
  • Always project-assigned — every temp belongs to a project via assignment. Temps never exist outside a project context.
  • Four scope types — project (standing workforce), task, session, or TTL. Duration varies by scope.
  • Lightweight identity — has name and role but no deep personality or long-term relationship
  • Project-level access — full access to project secrets, connectors, and memory. Auto-revoked on expiration.
  • Single-project memory — receives org + assigned project memory. No cross-project knowledge. Contributions attributed to task/project scope, not the temp's identity.
  • Concurrent limit — max 10 active per org (configurable)

Best for

Project-scoped workers (standing workforce), task-scoped workers (specialized one-off work), code reviewers (applying a rubric), burst parallelism. Promotable to staff via Lori.

The Dividing Line

If the role's value comes from remembering past decisions and carrying context across projects, it is staff. If the role applies skills to a task and moves on, it is temp.
Accumulated Judgment PMs — always staff. Org coordinators, policy reviewers, architecture reviewers, content reviewers — staff when cross-project judgment matters.
vs.
Fixed Rubric Project workers — the standing workforce. Task workers, code reviewers (rubric in skills), burst parallelism.

Lori selects a template, adapts the system prompt for the org's needs, adjusts the name and personality, and proposes the draft to the human for approval.

Custom agents created from scratch when no template fits. Custom profiles can be saved back to the catalog.

For Temp Instantiation

The PM or system selects a template matching the flow node's requirements. The temp is instantiated with the template's prompt and skills, scoped to the project or task.

Templates tagged by domain (frontend, backend, DevOps, QA, etc.) and by recommended class (staff or temp).

7-Layer Prompt Assembly

When an agent takes a turn, OtterCamp assembles the prompt from seven layers in priority order. Layers 1–2 are never cut. Layers 3–7 are budget-dependent and compressed as needed. Assembly runs once per turn — within the tool loop, iterations just append.

1

Agent Identity never cut

Core system prompt from the agent profile — who it is, how it thinks, its role. The agent's personality and expertise.

2

Policies & Constraints never cut

Org policy + project policy + agent policy_addendum + control plane capabilities. Safety-critical. Includes tool allow/deny communicated in natural language.

3

Scope Context budget-dependent

Determined by session scope: org (portfolio summary, priorities), project (description, architecture decisions), or task (acceptance criteria, constraints, relevant files).

4

Skills Instructions budget-dependent

Resolved from active skills only. Flow-node-relevant skills are loaded. Org/project defaults always included. An agent writing a blog post does not get deployment instructions.

5

Memory budget-dependent

Ellie's passive retrieval, scoped to the session. Top-k results injected automatically. In async mode, supplemented by active memory.query tool calls.

6

Conversation History budget-dependent

Session messages: recent turns in full, older turns summarized at checkpoints. Compressed further if budget requires.

7

Tool Descriptions lowest priority

Available tools filtered by agent's tool policy + control plane capabilities. Rarely an issue — tool descriptions are small relative to other layers.

Highest priority at top. Identity and policies are sacrosanct — everything else bends to the token budget.

Assembly Process

Step 1
Reserve
Calculate fixed-cost layers (identity + policies). These always go in.
Step 2
Allocate
Remaining token budget splits between scope, skills, memory, conversation, tools.
Step 3
Fill
Populate each layer up to allocation. Unused budget flows to lower-priority layers.
Step 4
Compress
If over budget: summarize history, then reduce memory. Identity and policies are never cut.

Nondeterministic Idempotence (NDI)

The path through a workflow is nondeterministic — different sessions may take different approaches. But the outcome is idempotent: acceptance criteria define "done," regardless of how many sessions it took.

Work State Is External

Flow nodes, task descriptions, acceptance criteria, and artifacts live in the database, not in agent context. Incremental progress survives session boundaries.

Memory Bridges Sessions

Ellie's extraction pipeline ensures that knowledge from a failed or exhausted session is available to the next one. No replaying — the new session assesses current state and moves forward.

Acceptance Criteria Are the Contract

A flow node is complete when its criteria are met. Whether that took one session or three is an implementation detail. The PM detects stuck nodes and escalates.

Project Staffing & Roles

Projects are staffed conversationally through Lori. She recommends agents, the human approves. Each agent assigned to a project holds one or more roles.

Four Project Roles
PM project_manager exactly one, mandatory, always staff
W worker executes task work, typically temps
R reviewer code: typically temp; policy/content: typically staff
P planner assists PM with scoping (optional)

An agent can hold multiple roles in the same project and different roles across projects.

The PM Is Special
  • Designs flow templates for the project
  • Scopes tasks with sufficient context
  • Triages blockers (agent → PM → Frank → human)
  • Proactive supervision of stuck agents
  • Default responder in project sessions
  • Private memory enabled by default

Enforced at database level: partial unique index on agent_project_assignment.

Flow Node Actor Resolution
1 role Resolve to assigned agent. For temp-default roles (worker, code reviewer), spins up a new temp using project template. Multiple agents? Lowest workload wins.
2 project_manager Resolve to the project's PM.
3 agent Resolve to a specific agent by ID.
4 human Creates an inbox item for human action.

Agent Concurrency

Agent identity is stateless at the prompt level. Two simultaneous turns by the same agent are independent model calls with no shared mutable state. There is no "Frank runtime" holding state between turns.

Stateless Identity

Everything assembled fresh from profile, scope context, memory injection, and conversation history on every turn. No coordination needed between concurrent sessions.

Concurrency Limits
GGlobal captotal concurrent LLM calls
PPer-providermodel provider rate limits
QPriority queuesync > async
Memory Concurrency

Concurrent private-memory writes handled by database transactions. Ellie's capture pipeline is event-driven and idempotent.
