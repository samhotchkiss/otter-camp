Ellie's Dual Role

Ellie is both the background memory infrastructure and a conversational agent. This dual role gives the memory system agency -- it can proactively surface context, ask clarifying questions, and explain its reasoning.

Background Infrastructure
  • Extraction -- monitoring events, extracting structured claims
  • Taxonomy management -- creating, merging, pruning the global tree
  • Entity synthesis -- consolidating scattered facts into definitional memories
  • Deduplication -- periodic LLM-powered dedup for memory hygiene
  • Consolidation -- distillation, contradiction detection, decay
  • Import processing -- extracting memories from JSONL archives
Conversational Agent (via @mention)
  • Answer memory queries -- "What do we know about X?"
  • Explain retrieval -- "Why did you surface that?"
  • Show entity knowledge -- "Tell me everything about [entity]"
  • Show belief history -- traverse the supersession chain
  • Explicit capture -- "Remember this: [statement]"
  • Corrections -- "That's wrong, actually [correction]"
  • On-demand ops -- "Run dedup" / "Re-synthesize [entity]"
  • System health -- counts, extraction activity, friction signals

Three Memory Layers

Durable memory is organized into three layers with distinct decay characteristics. Working memory (live context window) is NOT Ellie's domain -- it is handled by progressive summarization in the chat system.

Episodic
"What happened and what was the result?"
Time-stamped records of events, outcomes, decisions, conversations. High fidelity when captured, compacted over time through consolidation.
Decays unless reinforced
"The deploy to production failed on Friday because the CI cache was stale."
Semantic
"What do we know to be true?"
Distilled facts and typed claims: entity facts, relationships, preferences, conventions. Includes entity synthesis memories.
Durable -- no time decay
"OtterCamp uses PostgreSQL for all persistent data."
Procedural
"How do we do things well?"
Learned patterns and heuristics extracted from experience. Advisory, not prescriptive -- distinct from human-authored skills.
Decays without reinforcement
"When deploying on Fridays, run the full test suite twice -- Friday deploys have a higher failure rate."

Retrieval Pipeline

Every retrieval query passes through four stages. Taxonomy classification doubles as the query router -- different taxonomy branches naturally route to different memory populations and retrieval strategies.

Stage 1
Scope Filter
Reads agent's memory_read_scopes array (org, assigned_projects, current_task). Translates to SQL: org-scoped, project-assigned, task-matched. Agent-private memories of other agents always excluded.
Hard isolation
Stage 2
Taxonomy Classification
Classify query into taxonomy nodes. Also serves as the query router -- different branches route to optimal strategies.
Fallback: skip if low confidence
Stage 3
Subtree Retrieval
Pull all memories tagged with identified taxonomy nodes including children. Narrows from thousands to a focused, topically relevant subset.
Pre-filter for vector search
Stage 4
Relevance Ranking
Vector similarity (1536d cosine), recency, confidence, layer priority. Active queries add cross-encoder reranking.
Top-k within budget
Passive Injection

Automatic every turn. Budget-aware. Injection cooldown prevents repetition. Most relevant memories injected last (attention-aware ordering).

Active Query

Via @mention. Deeper search, broader scope. Cross-encoder reranking for precision. Can cross scope boundaries with explicit request.

memory.query Tool

Agent-initiated. Fills the gap between passive and active. Only fires when the agent recognizes uncertainty mid-turn. Excludes already-injected memories.

Experimentally Prohibited

V1's 48-hour experiment sprint on 13,000+ memories with a 20-query benchmark produced hard constraints. These techniques were tested, measured, and rejected.

Prohibited
Hybrid BM25 + Vector
-5pp (80% to 75%)
BM25 noise dilutes good vector matches on semantic queries. Only helps exact keyword matches (proper nouns) but hurts everything else.
Prohibited
Importance-Weighted Retrieval
-4pp overall
Importance scores from extraction are unreliable as retrieval weights. Confidence/utility used for lifecycle decisions only.
Prohibited
Kind-Aware Filtering
-2pp vs baseline
Marginal complexity for no gain. Kind is useful for taxonomy routing, not retrieval filtering.
-3pp File-only retrieval loses rich conversation context
-10pp Truncated 1536d to 768d embeddings -- never truncate

Lifecycle Events

Consolidation is progressive and ongoing. Two key triggers drive the most impactful memory processing: task completion and sleep-time reflection.

Task-Completion Consolidation
Trigger: task reaches "done" status
  1. Scope promotion -- LLM-based assessment: promote reusable knowledge (decisions, patterns) to project scope; keep task-specific working context for natural decay
  2. Episodic distillation -- distill task episodic memories into semantic memories while context is freshest
  3. Execution summary -- generate procedural memory with tool choreography: tools used, invocation order, which sequences led to success/failure
  4. Targeted entity synthesis -- run entity synthesis for entities heavily mentioned during the task
Sleep-Time Reflection
Trigger: low-activity periods + friction signals
  1. Gather -- collect recent episodic memories (last N days, configurable)
  2. Group -- organize by project and taxonomy
  3. Reflect -- LLM pattern recognition: what patterns emerge, what connections, what trends
  4. Generate -- create new semantic or procedural memories from reflections
  5. Cross-connect -- identify cross-project connections (e.g., shared API rate limits)

9-Table Schema

PostgreSQL with pgvector (1536d OpenAI embeddings, never truncated). Scoped across four levels: org, project, task, and agent-private. All memories require provenance -- no orphaned records.

memory
Core memory record with scope, kind, layer, status, is_hardened (provisional vs fully retrievable), confidence, temporal bounds, supersession chain, sensitivity, content hash, and 1536d embedding. CHECK constraints on kind, layer, status, archived_reason, and sensitivity.

Global taxonomy tree. Org-level, not per-project. Materialized path for fast subtree queries. Managed autonomously by Ellie.

Many-to-many link between memories and taxonomy nodes. Multi-label: a memory can belong to multiple nodes.
