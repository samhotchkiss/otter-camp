02 // Profiles

Profile Hierarchy

Model profiles bundle provider + model + settings + fallback chain into a single versioned entity. Resolution walks four levels -- the first non-null value wins.

1
Flow Node Override
A specific step in a task flow specifies a profile override. Use case: a code review node that needs a strong reasoning model, or a triage node using a cheap model.
Highest Priority
2
Agent Default
The agent's own profile specifies a default model profile. This is the standard model for that agent unless a flow node overrides it.
Per-Agent
3
Project Default
The project specifies a default profile for agents that don't have their own. "All agents in this project use Claude Sonnet unless specified otherwise."
Per-Project
4
Org Default
The organization-level fallback. If no profile is found anywhere else in the hierarchy, this is used. At least one org-level default is required.
Lowest Priority
System profiles (summarization, listening eval, memory extraction/synthesis) are resolved separately from this hierarchy. They are configured at the org level and are not overridable per-project or per-agent. They are infrastructure, not creative choices.

03 // Concurrency

Priority Queue

The gateway manages concurrency with global + per-provider limits and a four-tier priority system. Within tiers, requests are FIFO. Sync work can soft-preempt async work.

Highest Priority Queue Timeout
P1
Sync Interactive
Human is typing and waiting for a response. Latency directly impacts user experience. Can preempt async work at full capacity.
30s timeout
P2
Sync System
System calls supporting sync sessions: listening eval, summarization triggered during a sync turn. Must be fast -- the human is indirectly waiting.
15s timeout
P3
Async Agent
Autonomous agent work on tasks. Latency is acceptable. Can be soft-preempted by sync requests -- paused, not cancelled, and resumed when a slot opens.
5m timeout
P4
Async System
Background system operations: memory extraction, sleep-time reflection, scheduled maintenance. Patient work that runs when resources are available.
30m timeout
Soft Preemption: When a sync request arrives and all slots are occupied by async work, the most recently started async session is paused. Its current model call completes, but it is not dispatched for the next tool loop iteration. It returns to the queue with its original priority and resumes when a slot opens. This is pause, not cancellation.

05 // Budgets

Budget Enforcement

Two-level budget enforcement (org + project) with soft warn and hard block thresholds. Budget checks are optimistic -- they verify current spend is below the hard limit at routing time. In-progress calls may slightly exceed.

Normal Operation
Spend is below the soft limit. All invocations proceed normally. Cost is tracked per-invocation and rolled up incrementally.
Soft Limit Reached
Spend crosses the soft threshold. The system emits a warning event. The operator, PM, and Frank receive notifications. Work continues uninterrupted.
Warning Event Emitted Operator Notified Work Continues
Hard Limit Reached
Spend crosses the hard threshold. All new model invocations are rejected. In-progress calls complete. Queued invocations fail with budget_exhausted. Async work is paused, not cancelled.
New Calls Rejected Queue Paused PM Notified Inbox Item Created
Human Resolution
The human receives an inbox item: "Project X has reached its cost limit. Increase the budget or cancel pending work." Two paths forward.
Increase Budget (work resumes) Cancel Pending Tasks

06 // Reliability

Retry and Fallback Chains

When a model invocation fails, the gateway retries with exponential backoff (max 2 retries), then walks the fallback chain sequentially (max 3 profiles deep). The caller sees one request and one result -- all recovery is internal.

Retry Logic
Max 2 retries per call. Base backoff: 1s with 2x multiplier (1s, 2s). Random 0-500ms jitter added. Rate-limited errors use the provider's Retry-After header.
Fallback Constraints
Context window must fit the prompt. Tool call policy must be compatible. If fallback cannot fit the prompt (even after truncating history), it is skipped. Circular references rejected at config time.
Error Classification
8 canonical error classes. Retryable: rate_limited, overloaded, timeout, network_error, provider_error. Non-retryable: auth_failed, invalid_request, model_unavailable (triggers fallback instead).
07 // Schema

Database Schema

Six tables covering provider registration, profile management, invocation tracking, cost aggregation, and budget enforcement.

model_provider Instance-Level
id uuid PK
slug text unique
adapter_type text
is_enabled boolean
base_url text nullable
Registered by the instance operator. Maps slugs (anthropic, openai, google, openai-compat) to adapter implementations. base_url is the default API endpoint.
model_provider_config Per-Org
id uuid PK
organization_id uuid FK
provider_id uuid FK
api_key_secret_ref text
max_concurrent int nullable
Per-org activation and credentials. API keys stored as encrypted secret references, never plaintext. Unique constraint on (organization_id, provider_id).
model_profile Versioned
id uuid PK
slug / version text / int
provider_id / model_id uuid / text FK
max_input / output_tokens int / int
temperature / top_p / top_k numeric
pricing fields (4) numeric(12,8)
fallback_profile_id uuid nullable FK self
Core abstraction. Versioned profiles with generation settings, token limits, pricing, tool/streaming policy, timeout, cost limit, retry count, and fallback chain. Unique on (org, slug, version).
model_profile_assignment Hierarchy
id uuid PK
scope_type text
scope_id uuid
profile_id uuid FK
pinned_version int nullable
Implements the 4-level hierarchy: scope_type is one of org, project, agent, flow_node. One assignment per scope (unique constraint). Pinned version locks to a specific profile version.
model_invocation Per-Call Audit
id uuid PK
attribution (5 dims) uuid nullable FKs
token counts (4) int
estimated_cost_usd numeric(10,6)
prompt/response refs text (obj store)
parent_invocation_id uuid nullable FK self
One row per model call. The most granular record in the system. Captures tokens, cost, latency, attribution, outcome, error class, retry/fallback chain, and prompt capture references. 11 partial indexes for fast queries.
model_cost_rollup / budget Aggregation
rollup: rollup_type org/project/agent/model
rollup: period_start/end date
rollup: total_cost_usd numeric(12,4)
budget: soft/hard_limit numeric(12,4)
budget: current_spend numeric(12,4)
Pre-computed daily rollups (4 dimensions) updated atomically per invocation. Budget table enforces soft warn + hard block at org and project levels. Monthly period with custom period option.
