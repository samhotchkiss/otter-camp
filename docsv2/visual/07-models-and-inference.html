Gateway Architecture

02 // Profiles

Profile Hierarchy

Model profiles bundle provider + model + settings + fallback chain into a single versioned entity with a stable logical identity. Resolution walks four levels -- the first non-null value wins.

1
Flow Node Override
A specific step in a task flow specifies a profile override. Use case: a code review node that needs a strong reasoning model, or a triage node using a cheap model.
Highest Priority
2
Agent Default
The agent's own profile specifies a default model profile. This is the standard model for that agent unless a flow node overrides it.
Per-Agent
3
Project Default
The project specifies a default profile for agents that don't have their own. "All agents in this project use Claude Sonnet unless specified otherwise."
Per-Project
4
Org Default
The organization-level fallback. If no profile is found anywhere else in the hierarchy, this is used. At least one org-level default is required.
Lowest Priority
System profiles (summarization, listening eval, memory extraction/synthesis) are resolved separately from this hierarchy. They are configured at the org level with a system_purpose field and are not overridable per-project or per-agent.

04 // Concurrency

Priority Queue

The gateway manages concurrency with global + per-provider limits and a four-tier priority system. Slots are held per-model-call, not per-turn. Sync work can soft-preempt async work.

Highest Priority Queue Timeout
P1
Sync Interactive
Human is typing and waiting for a response. Latency directly impacts user experience. Can preempt async work at full capacity.
30s timeout
P2
Sync System
System calls supporting sync sessions: listening eval, summarization triggered during a sync turn. Must be fast -- the human is indirectly waiting.
15s timeout
P3
Async Agent
Autonomous agent work on tasks. Latency is acceptable. Can be soft-preempted by sync requests -- paused, not cancelled, and resumed when a slot opens.
5m timeout
P4
Async System
Background system operations: memory extraction, sleep-time reflection, scheduled maintenance. Patient work that runs when resources are available.
30m timeout
Slot Holding: Concurrency slots are held per-model-call, not per-turn. Between model calls (during tool execution), the slot is released. The session re-enters the queue for its next model call. This makes preemption naturally efficient -- when a sync request arrives, the most recently started async session finishes its current call, then pauses.
05 // Failover

Connection Failover

When a connection fails, the gateway tries same-provider alternatives first, then cross-provider fallback profiles. Every failover event notifies the human in real-time.

1. Try Primary Connection
Gateway selects the healthiest connection for the resolved profile's provider. If it succeeds, the request completes normally.
2. Retry on Failure
For retryable errors (rate_limited, overloaded, timeout, network_error), retry up to 2x with exponential backoff (1s, 2s) plus jitter. Rate-limited errors respect Retry-After.
Backoff: 1s, 2s Jitter: 0-500ms
3. Same-Provider Failover
If the org has multiple connections to the same provider, try the next healthiest one. Same model, different API key. Least disruptive path.
Same Model Different Key
4. Cross-Provider Fallback
If all connections for the current provider are exhausted and the profile has a fallback_profile_id, switch to a different provider entirely. Chain depth max: 3 profiles.
Different Provider Max 3 Deep
5. Notify Human
Every failover event generates a real-time notification: what happened, what the system did, and the current connection state. Frequent failovers escalate to a prominent alert.
Inbox Notification Real-time Event Frequency Alert
06 // Schema

Database Schema

Six tables covering provider registration, multi-key connection management, profile versioning with stable logical identity, invocation tracking, and token usage rollups.

model_provider Instance-Level
id uuid PK
slug text unique
adapter_type text
is_enabled boolean
base_url text nullable
Registered by the instance operator. Maps slugs (anthropic, openai, google, openai-compat) to adapter implementations. base_url is the default API endpoint.
provider_connection Multi-Key
id uuid PK
organization_id uuid FK
provider_id uuid FK
label text
health_status text
failover_priority int
total_input/output_tokens bigint
Multiple connections per provider per org. Health tracking (healthy/degraded/rate_limited/unavailable), failover priority ordering, cumulative stats, rate limit state. API keys stored as encrypted secret refs.
model_profile Versioned
id uuid PK
logical_profile_id uuid
slug / version text / int
provider_id / model_id uuid / text FK
max_input / output_tokens int / int
system_purpose text nullable
fallback_profile_id uuid nullable
Stable logical_profile_id across versions. Assignments and fallback chains reference logical ID. Generation settings, token limits, tool/streaming policy, timeout, retry count. system_purpose for programmatic lookup of system profiles.
model_profile_assignment Hierarchy
id uuid PK
scope_type text
scope_id uuid
profile_id uuid (logical) FK
pinned_version int nullable
Implements the 4-level hierarchy: scope_type is one of org, project, agent, flow_node. profile_id references logical_profile_id for stability. Single source of truth for all model assignments including flow node overrides.
model_invocation Per-Call Audit
id uuid PK
connection_id uuid FK
attribution (5 dims) uuid nullable FKs
token counts (4) int
prompt/response refs text (obj store)
retry_of / fallback_of uuid nullable FK self
One row per model call. Captures tokens, latency, attribution, connection used, outcome, error class. Separate retry_of and fallback_of FKs for unambiguous chain reconstruction. System profile calls attributed to triggering agent.
model_usage_rollup Token Rollups
rollup_type connection/model/agent/project
period_date date
total_input_tokens bigint
total_output_tokens bigint
total_errors int
Pre-computed daily token rollups across 4 dimensions. Updated atomically per invocation. Powers the subscription dashboard and usage analytics. All org-scoped. Includes cache token counts.
