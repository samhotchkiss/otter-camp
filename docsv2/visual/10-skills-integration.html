Doc 10 -- Skills Integration

Skills Integration

Skills are markdown instruction documents that get loaded into an agent's prompt when relevant. They shape how the agent behaves for a specific type of work.

Instructions, Not Code. A skill is a plain markdown file with YAML frontmatter. No executable logic, no templating, no imports. Skills are documents that tell an agent how to do something -- nothing more.

Anatomy

What a skill file looks like

YAML frontmatter carries metadata. The markdown body carries the instructions that get injected into the agent's prompt at runtime.

skills/go-coding-standards.md 
---
name: Go Coding Standards
slug: go-coding-standards
scope: project
category: engineering
description: Conventions and patterns for Go code in this project.
---

## Error Handling

Always return errors rather than panicking. Use `fmt.Errorf` with `%w`
for wrapping. Never silently discard errors.

## Naming

Use camelCase for unexported identifiers, PascalCase for exported.
Package names are lowercase, single-word. No underscores.

## Testing

Every exported function has at least one test. Table-driven tests for
functions with multiple input cases.

YAML Frontmatter

Metadata only: name, slug, scope, category, description, and an optional default: true flag. This data lives in the skill registry table, not the prompt.

Markdown Body

The actual instructions. This is the content that gets loaded into the agent's prompt at runtime. Plain markdown -- no templating, no conditionals, no executable code.

Attachment

Four levels of specificity

Skills attach at four levels, from broadest to narrowest. Each level narrows the scope and increases the specificity of the instructions.

Broadest scope
Level 1
Org Defaults
Apply to all work across all projects in the organization. Set via default: true in an org-scoped skill. Never cut from the prompt.
Safety policies, communication guidelines
Level 2
Project Defaults
Apply to all work within a single project. Set via default: true in a project-scoped skill. Never cut from the prompt.
Coding standards, architecture conventions
Level 3
Agent-Level
Part of the agent's profile. Define the agent's identity and core competencies. Linked via the agent_skill table. High priority in budget allocation.
Frank identity, PM planning skill
Level 4
Flow Node
Activated only for a specific workflow step. The most targeted: an agent writing a blog post gets blog-writing skills, not deployment skills. Linked via the flow_node_skill table.
Code review checklist, blog writing guidelines
Most specific
Activation

Token budget efficiency

An agent may have many skills available, but only relevant ones are activated and loaded into the prompt. This keeps prompts focused and respects the context window budget.

Content Source

Skill content is read from the git repo at prompt assembly time. Not cached in the database. Changes take effect on the next turn after commit.

Management

The PM agent manages all skill CRUD through conversation and git commits. There is no skill editor UI. Everything happens through chat.

Conflicts

Specificity resolution

When multiple activated skills contain conflicting instructions, the most specific wins. The agent is told the resolution order in its prompt so it knows which instruction takes priority.

Example: Indentation style conflict
1
Flow Node Skill
"Use tabs for indentation in generated config files"
Wins
2
Agent-Level Skill
"Default to 4-space indentation"
Overridden
3
Project Default
"Use 2-space indentation"
Overridden
4
Org Default
"Follow standard formatting"
Overridden
Skills always win over procedural memory. Skills (layer 4) are prescriptive directives. Procedural memory (layer 5) is advisory -- the agent can use it or ignore it. If they conflict, the skill wins. Always.
Prompt Assembly

Layer 4 of 7

Skills occupy layer 4 in the prompt assembly pipeline -- after scope context, before memory. Content is ordered by precedence: org defaults first, flow node skills last (later content has higher weight).

1
Agent Identity
Never cut
2
Policies and Constraints
Never cut
3
Scope Context
Org, project, or task context
4
Skills Instructions
This layer -- activated skills from git
5
Memory
Advisory, defers to skills
6
Conversation History
Budget-managed
7
Tool Descriptions
Available capabilities

Injection Format

Each skill is injected with a header identifying its source and level: === Skill: Go Coding Standards (project default) === so the agent can reason about conflicts.

Token Budget

Recommended maximum of ~4,000 tokens per skill. Org/project defaults are never cut. Identity skills are high priority. Non-default agent skills are cut first when budget is tight.

Bootstrap

Skills that ship on day one

V2 ships with identity skills for the starter trio, a PM identity skill, and org-wide system skills. Project template skills are available for adoption but not pre-installed.
