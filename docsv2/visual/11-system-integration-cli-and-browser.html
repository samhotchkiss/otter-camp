CLI Command Policy

Risk Classification Matrix

Every CLI command is classified by risk level before execution. Policy decisions are binary: allow or deny. Permissions are configured in advance, not resolved at runtime. Compound commands are decomposed and classified by their riskiest component.

Safe
Default: Always allowed

Read-only operations and standard development commands. No side effects.

  • ls, cat, grep
  • go build, npm test
  • git status, git diff
  • git log, git show
Normal
Default: Allowed (configurable)

Commands with side effects expected in development workflows.

  • go run, npm install
  • pip install, make
  • git commit
  • git push (task branch)
Sensitive
Default: Denied (configurable via org/project policy)

Commands that could have significant impact. Network calls, containers, publishing.

  • curl, wget
  • docker run
  • Package publishing commands
  • System config modifications
Dangerous
Default: Denied

Destructive or system-integrity commands. Never allowed by default. Denylist enforced.

  • rm -rf /, mkfs
  • shutdown, reboot
  • sudo, su, chmod +s
  • kill -9 1, iptables
Policy Layer Hierarchy
1

Instance Safety Policy

Default denylist. Cannot be overridden by any lower layer.

Highest
2

Organization Policy

Org-wide additions to denylist or risk classification adjustments.

High
3

Project Policy

Project-specific overrides. A deploy project might allow docker build at normal risk.

Medium
4

Agent Profile Policy

Per-agent restrictions. A content writer has no business running docker.

Lowest

Lower layers can only restrict, never loosen, what higher layers have denied.

Sandboxing

CLI Execution Environment

The execution environment is constructed, not inherited. Agents get the minimum access needed for their task, with full isolation from the host system and other projects.

Working Directory

  • Scoped to project git repo at task branch HEAD
  • Path traversal outside repo is rejected
  • No access to other projects or host filesystem
  • Read: repo + system packages + temp dirs
  • Write: repo + designated temp dirs only

Constructed Environment

  • HOME = temp dir, TERM = dumb
  • PATH restricted to standard + project tools
  • Project vars injected encrypted at runtime
  • Org secrets resolved from secret store
  • Model provider keys blocked (OPENAI, ANTHROPIC)

Network Policy

  • allow_all -- unrestricted outbound (default)
  • deny_all -- no network connections
  • allowlist -- specified hosts/CIDRs only
  • Enforced at process level (iptables or equivalent)

Time Limits

  • Default per-command timeout: 5 minutes
  • Max allowed timeout: 30 minutes (org config)
  • Enforcement: SIGTERM then SIGKILL after 10s
  • Counts against turn max_duration budget

Process Isolation

  • Dedicated OS process, restricted privileges
  • Service user with no elevation
  • Max memory: 2GB default (configurable)
  • Child processes tracked and terminated on exit
  • No persistent background daemons

Git Branch Rules

  • Work on task branch: add, commit, stash, rebase
  • Read-only on any branch: log, diff, show, blame
  • Denied: push to main, force push, branch -D
  • Push to task remote: sensitive (policy tracked)
Browser Action API

Structured Browser Actions

Agents express intent through structured actions, not raw Playwright or Puppeteer code. This keeps prompts clean, actions auditable, and sandboxing enforceable. Automatic screenshots after every action provide a full visual audit trail.

Navigate

Control browser navigation with domain policy enforcement. Redirects to blocked domains are caught and halted.

  • browser.navigate({url})
  • browser.back()
  • browser.forward()
  • browser.refresh()

Interact

Click elements, type text, select options, hover, scroll. CSS selector or accessibility-based locators.

  • browser.click({selector})
  • browser.type({selector, text})
  • browser.select({selector, value})
  • browser.hover({selector})
  • browser.scroll({direction})
  • browser.press_key({key})

Observe

Screenshot capture, text extraction, structured data scraping, and page state inspection for the agent.

  • browser.screenshot({full_page})
  • browser.extract_text({selector})
  • browser.extract_structured({schema})
  • browser.get_page_info()

Wait

Wait for elements or navigation to complete. Prevents acting on pages that have not finished loading.

  • browser.wait_for({selector, state})
  • browser.wait_for_navigation()
  • States: visible, hidden, interactive
  • Default timeout: 30s interactions, 60s nav

Domain Policy

  • allow_all -- any domain (default)
  • denylist -- block specific domains
  • allowlist -- only specified domains
  • Sensitive domains (financial, auth, admin, email) denied by default; allowlisted per org/project

Credential Injection

  • Agents never see credentials in prompts
  • Cookies/tokens injected at session creation
  • Resolved from org secret store at runtime
  • Audit trail never contains raw secrets

Session Lifecycle

  • Task-scoped: persists across runs within a task
  • One active session per task at a time
  • Idle timeout: 1 hour (configurable)
  • Cleanup on task done, cancelled, or revoked
Human Handoff

CAPTCHA / 2FA / Payment Handoff Flow

When automation hits limits -- CAPTCHA, two-factor auth, payment, or policy-flagged actions -- the browser session is handed to the human. The agent pauses, the human completes the sensitive action, and the agent resumes from the human-modified state.

Artifact Management

Output Handling and Artifacts

Every execution surface produces artifacts. CLI output is truncated in tool results with full content stored in RunArtifacts. Browser screenshots are captured automatically after every action for the human audit trail.

CLI Output

Inline limit (tool result) 50 KB per stream
Total capture limit 10 MB per command
Streaming events cli.stdout, cli.stderr, cli.exit
Overflow handling Truncated + artifact_id ref
Artifact types cli_output, build_output, test_report
Retention (after task) 30 days default

Browser Artifacts

Auto screenshots After every action
Screenshot storage RunArtifact (not inline)
Explicit screenshot Returned inline to agent (vision)
Max download size 100 MB per project (configurable)
Artifact types screenshot, download, extracted_data
Retention (after task) 90 days default
Database Schema

Four Domain Tables

These tables extend the control plane's Run/RunStep/RunArtifact framework with CLI and browser domain-specific detail. They reference the generic execution schema by ID without duplicating it.

cli_execution

Run-scoped

Full command lifecycle from policy evaluation through execution to output capture. Complements RunStep with CLI-specific detail.

id run_id run_step_id task_id project_id agent_id command working_dir risk_level policy_decision exit_code stdout_preview stderr_preview stdout_artifact_id stderr_artifact_id duration_ms status env_vars network_policy timeout_ms

browser_session

Task-scoped

Task-scoped, not run-scoped. Persists across runs within a task for multi-step workflows. Tracks domain policy and credential references.

id task_id project_id agent_id status domain_policy domain_rules credential_refs current_url current_title last_action_at close_reason

browser_action

Run-scoped

Fine-grained record of every browser interaction. Linked to both browser session (for context) and run/run_step (for control plane linkage).

id browser_session_id run_id run_step_id action_type action_params description page_url_before page_url_after success error_message screenshot_artifact_id extracted_data policy_decision duration_ms

browser_handoff

Session-scoped

Tracks the human handoff lifecycle. Bridges browser and inbox domains. Handoffs expire after 24 hours by default.

id browser_session_id inbox_item_id run_id reason agent_description page_url screenshot_artifact_id status human_completed_at post_handoff_screenshot_id expires_at
