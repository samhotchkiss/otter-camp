Event System

~70 Domain Events Across 11 Domains

Every significant state change emits a domain event into a durable PostgreSQL table. Events follow {domain}.{entity}.{action} naming. The outbox pattern guarantees at-least-once delivery to four consumer categories.

Event Structure

Uniform Event Envelope

{ "id": "evt_01H2X3Y4Z5...", "type": "task.flow.advanced", "timestamp": "2026-02-22T14:30:00.123Z", "actor": { "type": "agent", // human | agent | system "id": "uuid-of-agent" }, "scope": { "organization_id": "uuid", "project_id": "uuid", "task_id": "uuid", "session_id": null }, "payload": { // type-specific }, "metadata": { // operational } }

Dispatch Guarantees

Outbox Pattern -- Events are written in the same database transaction as the domain operation. No event is lost on crash.

At-Least-Once Delivery -- Consumers may receive the same event more than once. All consumers must be idempotent.

Poll Interval -- 100-500ms for low latency on realtime push. Batched under load.

Append-Only -- Events are never updated or deleted during normal operation. 90-day default retention.

Scope Denormalized -- org_id, project_id, task_id, session_id are columns, enabling efficient subscription filtering without JSON parsing.

Infrastructure

Job Queue -- Four Priority Tiers

PostgreSQL-backed job queue. No Redis. Workers claim jobs via SELECT ... FOR UPDATE SKIP LOCKED for concurrent claiming without contention. Exponential backoff retries, dead letter handling, stale claim recovery.

Sync / Human-Waiting 100

Human is actively waiting for a result. Picked first.

  • Agent turns (sync sessions)
  • Steer/cancel operations
  • Approval actions
Standard Async 50

Normal asynchronous work. Runs promptly, not urgently.

  • Agent turns (async)
  • Flow node starts
  • Merge execution
  • Push execution
Background 25

Processing that can tolerate some delay.

  • Memory extraction
  • Notification dispatch
  • Summary generation
  • Deploy task creation
Maintenance 10

Housekeeping. Runs when capacity allows.

  • Ephemeral message cleanup
  • Idempotency key purge
  • Event log retention
  • Memory consolidation

Retry Policy

Exponential backoff: base_delay * 2^(attempts - 1) with jitter

Base delay: 5s. Max delay: 5 min. Default max attempts: 3.

When attempts >= max_attempts, the job moves to dead_letter status.

Stale Claim Recovery

Background monitor watches for claimed jobs that exceed their timeout.

Agent turns: 30 min timeout. Lightweight jobs: 5 min timeout.

Stale jobs are reset to pending (if retries remain) or dead_letter. A system.job.failed event is emitted.

Realtime Transport

SSE Default, WebSocket Opt-In

Server-Sent Events is the primary transport for server-to-client push. WebSocket is available for bidirectional needs. Clients subscribe to hierarchical scopes and receive filtered events from the durable log.

Default

Server-Sent Events (SSE)

GET /v1/events/stream?scopes=org:uuid,project:uuid,session:uuid
  • DirectionServer to client (unidirectional)
  • ProtocolStandard HTTP -- works through proxies, CDNs, load balancers
  • ReconnectionBuilt-in via Last-Event-ID; replays missed events from durable log
  • AuthBearer token or session cookie
  • Keepalive:keepalive comment every 15 seconds
  • Scope changesRequires new connection (seamless via reconnect)
  • BackpressureBuffer up to 1000 events; overflow drops connection

Primary use cases

  • Streaming agent responses (message deltas)
  • Task status updates and flow progression
  • Notification delivery
  • Dashboard and project view updates
  • Merge queue and deploy status
Opt-in

WebSocket

GET /v1/ws?scopes=org:uuid,project:uuid -- Upgrade: websocket
  • DirectionBidirectional (client and server)
  • ProtocolProtocol upgrade from HTTP; may need proxy config
  • ReconnectionClient-managed; replay via event log query
  • AuthSame as SSE (Bearer / session cookie)
  • Client messagessubscribe, unsubscribe, typing indicators
  • Scope changesDynamic via client messages on same connection
  • BackpressureSame buffer overflow model as SSE

Specialized use cases

  • Typing indicators ("user is typing")
  • Interactive tool sessions (live pairing)
  • Future: voice-to-text streaming

Scope Hierarchy

org:{id}
Broadest scope. All events in the org. Includes all projects, tasks, sessions. Used by dashboards.
project:{id}
All events for a project: tasks, flow, merge, deploy. Used by project views.
task:{id}
Single task: status, flow, subtasks. Used by task detail views.
session:{id}
Single chat session: messages, deltas, turns, reactions. Used by the chat pane.
