Security

Defense in Depth -- Six Concentric Layers

No single mechanism is the sole defense. Every layer assumes the one above it might fail. The threat model centers on rogue agent behavior, not external attackers.

1

Org Isolation (Perimeter)

Hermetic organization_id scoping on every query. RLS in PostgreSQL. Cross-org data sharing does not exist.

2

Authentication

Email + password (bcrypt) or scoped API keys. Agents have no credentials -- identity is asserted by the platform.

3

Authorization

RBAC roles for humans, capability-based for agents. Default-deny posture. Three outcomes: allow, deny, require_approval.

4

Control Plane Gating

All agent mutations pass through the execution broker. No privileged path outside broker/worker. High-risk actions require human approval.

5

Agent Sandboxing

Constrained CLI, isolated browser contexts, per-connection MCP capability checks. Domain allowlists/denylists.

6

Audit Trail

Immutable, append-only audit events. Answers: who did what, when, where, and who authorized it.

Secret Management

Secret Lifecycle -- AES-256-GCM Encrypted at Rest

Master key provided by operator (env var or KMS). Per-secret unique nonce. Key version tracking for zero-downtime rotation.

Storage

AES-256-GCM encrypted in PostgreSQL. Unique nonce per secret. Plaintext never written to disk.

Decryption

Control plane worker decrypts in memory at execution time. Plaintext held only for operation duration.

Injection

Injected into sandboxed execution environment. Agent references secret by ID; platform resolves at runtime.

Discard

Plaintext discarded after operation completes. No caching. No persistence outside encrypted column.

Observability

Built-in Observability Stack

Built into the platform, not bolted on. Answers three questions: What are my agents doing? Is something wrong? What did it cost?

Layer 1

Structured Logging

JSON format with mandatory trace_id, component, and timestamp. Secret scrubbing before write. Output to stdout for infrastructure routing.

trace_id component org_id principal secret scrub
Layer 2

Distributed Tracing

OpenTelemetry-compatible. Follows requests through API, worker, model calls, tool executions. 100% default sampling; errors always captured.

OTLP trace_span table Jaeger Zipkin
Layer 3

Prometheus Metrics

Exposed at /metrics endpoint (pull model). Four categories: API, model, queue/execution, and memory metrics. Optional OTLP push for managed deployments.

API latency model cost queue depth memory retrieval
Layer 4

4 Built-in Dashboards

Overview, Cost, Performance, and Agents dashboards in the web UI. Self-hosted operators can also export to Grafana or Datadog.

Cost Controls

Multi-Dimensional Cost Attribution

Every ModelInvocation records per-request cost using a provider pricing table. Costs are aggregated into hourly, daily, and monthly summaries.

Per-Invocation Tracking

Every model call records provider, model, input/output tokens, and cost estimate in USD. Calculated at invocation time from pricing table.

provider + model input_tokens / output_tokens cost_estimate (USD) org_id / project_id / agent_id / run_id

Time-Series Aggregation

Background jobs roll up raw invocations into hourly, daily, and monthly summaries. Raw records retained 30 days; summaries retained indefinitely.

Hourly -- computed every hour Daily -- from hourly summaries Monthly -- from daily summaries

Attribution Dimensions

Costs are sliceable by organization, project, agent, provider, and model. Interactive drill-down in the Cost dashboard.

By organization (total cap) By project (project cap) By agent (top consumers) By provider + model
Budget Enforcement

Threshold / Soft Warn / Hard Block / Anomaly Detection

Hard limits fail closed -- they block execution and notify the human. They do NOT silently degrade to cheaper models. The human makes model selection decisions consciously.

Pre-Check

Broker checks current period spend against org + project budgets before dispatching.

Under Limit

Soft Warn

Spend exceeds soft limit. Run proceeds. Warning emitted once per budget per period.

Warn Once

Hard Block

Spend exceeds hard limit. Run blocked with budget_exceeded. Inbox item created for operator.

Fail Closed

Anomaly Detection

Every 15 min: if hourly spend exceeds 3x the 7-day average, alert the operator. Deduped to 1/hr/org.

Privacy & Retention

Configurable Retention Policies

Configurable per organization. Enforced by a daily background job. Audit events are archived before deletion -- never hard-deleted without archival.

Data Type Default Retention Rationale
Chat session transcripts 90 days Voluminous. Valuable context is extracted to memory. Raw transcripts useful for debugging, not indefinitely.
Memory items (active) Indefinite Distilled org knowledge. Own lifecycle (decay, consolidation, archival). Not deleted by retention policy.
Memory items (archived) 1 year Preserved for provenance and temporal queries. Purged after 1 year.
Audit events 1 yr (self-hosted) / 3 yr (managed) Security compliance record. Longer retention where compliance requirements are stricter.
Run records and events 90 days Execution history for debugging and cost analysis. After 90d, aggregate metrics suffice.
Model invocation logs 30 days Large and sensitive (contain prompts/completions). Token/cost aggregates retained indefinitely.
Object storage artifacts 90 days Screenshots, generated files, log outputs. Artifacts linked to active tasks are exempt until task completes.

GDPR-Aware Design

Not certified at GA. Architecture supports compliance when needed.

Right to Access

Export API generates JSON archive of all data associated with a human user via (principal_type, principal_id) convention.

Right to Erasure

Data deletion workflow across all tables. Audit events retained (legitimate interest) but can be anonymized.

Data Portability

Machine-readable JSON export: chat transcripts, memories, project data, and agent configurations.

Data Minimization

Retention policies ensure data is not kept longer than needed. Model invocation logs have shortest retention.
