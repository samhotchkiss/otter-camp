Clean Room
Rebuild

This is NOT a migration

V2 is a ground-up rewrite that shares no code, schema, or data with V1. V1 was architecturally bound to OpenClaw -- V2 replaces it entirely. The only bridge is an optional memory import. Everything else starts fresh.

No V1 Code Reused No Schema Migration Fresh Database Human-Initiated Cutover
Architecture Comparison

V1 vs V2: Different Worlds

V1 and V2 are fundamentally different architectures. There is no incremental path between them.

V1 -- Archived

  • Built on OpenClaw orchestration
  • Schema mirrored OpenClaw's entity model
  • API proxied OpenClaw interfaces
  • Two separate memory taxonomies
  • No scope isolation on memories
  • No entity synthesis table
  • No dedup tracking
  • No flow template or node tables
  • No control plane or policy engine
  • Cannot run without OpenClaw
vs

V2 -- Ground Up

  • Direct in-app orchestration
  • New domain model from first principles
  • Entirely new API design
  • Unified memory taxonomy (doc 06)
  • Org/project/task scope with foreign keys
  • Entity synthesis as core schema
  • Cursor-based dedup tracking
  • Full task flow system (doc 03)
  • Policy engine with layered evaluation
  • Zero external dependencies for orchestration

Medium-Low Trust

Imported V1 memories start with a confidence cap of 0.6 -- lower than V2-native conversations (0.8) or human statements (1.0). Historical data has not been verified in V2's context. Memories can be promoted through corroboration: if a V2 conversation confirms an imported fact, the confidence cap rises based on the new, higher-trust source.

Left Behind

What Does NOT Carry Over

Only memory crosses the bridge. Everything else is structural data that can be quickly recreated through conversation.

X

Chat History

V2's chat schema is fundamentally different. History is valuable only as a memory source (which JSONL import covers).

X

Projects

Structural data, not knowledge. Recreating project structure takes minutes through conversation with Frank.

X

Tasks

Incompatible schemas between V1 and V2. V2 introduces flow templates, nodes, and execution tracking.

X

Agent Configs

V2 agents have new prompt packs, tool policies, model policies, and memory policies. V1 configs are not compatible.

X

API Keys

V1 API keys do not work in V2. New keys must be created through V2's key management system.

X

Integrations

MCP connections, webhooks, scripts, and external UIs must all be rebuilt for V2's new API.

Cutover

The Human-Initiated Cutover

No automated migration phase. No parallel-run reconciliation. No cutover script. The human installs V2 and starts working.

1

Install V2

Deploy V2 with an empty database. Schema migrations run on startup.

2

Bootstrap

Starter trio seeded. Flow templates, safety policy, model profile created.

3

Import Memories

Upload V1 JSONL exports. Full pipeline processes them.

optional
4

Validate

Run pre-launch checklist. Confirm core workflows function.

5

Switch

Start using V2. Direct all new work here. V1 is archived.

Forward Only

If issues arise, fix them in V2. V1 rollback is last resort only.

Guiding Principles

Three Rules for the Clean Break

Clean-Room Rebuild

No V1 code, schema, or data is reused. V1 informs requirements, not implementation. V2's domain model, agent runtime, memory system, and control plane are all designed from first principles. V1 is read for reference only -- no function, module, or package is imported.

V1 informs requirements, not implementation

Forward-Only Recovery

If V2 has issues, fix them in V2. V1 restoration is a documented last resort that depends on OpenClaw availability and loses all V2-era data. The modular monolith architecture and Docker Compose deployment are designed for rapid iteration. Bugs are fixed and deployed, not recovered by reverting.

Fix forward, don't roll back

Human-Initiated Cutover

There is no automated migration phase, no parallel-run reconciliation, and no cutover script. The human installs V2, bootstraps it, optionally imports V1 memories, and starts working. Migration is not a phase -- it is the absence of one.

No cutover script. Just start using V2.
