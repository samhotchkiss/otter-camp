01 // Layout

Three-Panel Terminal Layout

Chat is the primary interface, not a sidebar accessory. The chat pane gets 40% of the screen. Main content gets 40%. The sidebar navigator takes 20%. Exactly one panel has focus at a time -- bright border on the focused panel, dim on the rest.

Focus cycling: Tab / Shift-Tab cycles panels. Alt-1 / Alt-2 / Alt-3 jumps directly. The focused panel has a bright border and captures all keyboard input. Context-appropriate keybinding hints appear in the status bar.

02 // Dual Modes

One Binary, Two Modes

The otter binary serves two purposes. Both connect directly to the OtterCamp API via HTTP + SSE -- the TUI is an API client, same as the web UI will be.

otter tui

interactive
$ otter tui

Full-screen, persistent, real-time. The sustained interaction mode for chatting with agents, monitoring work, reviewing tasks, and managing the operation.

  • Three-panel layout with live updates
  • Streaming agent responses (SSE)
  • Vim-style navigation throughout
  • Command palette with fuzzy matching
  • Session state persists across launches
  • Markdown rendering via Glamour

otter <command>

scriptable
$ otter send "deploy the landing page"

Quick, non-interactive, pipe-friendly. For scripting, automation, and quick one-off actions from the shell.

  • Plain text output (default) or JSON (--json)
  • Composable with Unix tools (pipe, grep)
  • Integration with shell workflows
  • otter send, status, inbox, task, projects...
  • otter inbox approve <id>
  • Works in scripts, cron jobs, CI/CD
CLI command examples 
$ otter status
Inbox: 3 items  |  Active tasks: 6  |  Queue depth: 2  |  Connected

$ otter inbox --json | jq '.[] | select(.urgency == "high")'
{ "id": "abc123", "type": "escalation", "title": "Auth conflict" }

$ otter send --to frank "$(git log --oneline -5)"
Message sent to Frank (org session)

$ otter task OC-5
OC-5: Implement Auth Middleware     [HIGH]  [in_progress]
Branch: task/implement-auth
Subtasks: 2/3 done  |  Flow: [x Design]->[* Implement]->[ Review]->[ Final]

04 // Scope Switching

Context Without Navigation

The scope indicator at the top of the chat pane lets the operator switch between org, project, and task scopes using [ and ] keys -- without changing the main content view. Talk to Frank at org scope while looking at a task detail.

Project OtterCamp V2
-->
Org General

05 // Realtime Updates

SSE Event Stream

The TUI maintains a persistent SSE connection to the OtterCamp API. Events drive UI updates without polling. Auto-reconnect with exponential backoff. Missed events recovered via sequence-based catch-up.

SSE Event Mapping

event types --> UI updates 
Event Type                        Panel Updated
-----------------------------------------------------------
chat.message.created       -->  Chat pane (or unread indicator)
chat.message.delta         -->  Chat pane (streaming text)
chat.message.finalized     -->  Chat pane (message state final)
chat.turn.started          -->  Active turn indicator shown
chat.turn.completed        -->  Turn indicator cleared
task.status.changed        -->  Task board, task detail, dashboard
task.flow.advanced         -->  Flow stepper updates
inbox.item.created         -->  Inbox count + sidebar badge

agent.run.completed        -->  Agent status view
merge.status.changed       -->  Merge queue view

Connection status:  [*] connected   [*] reconnecting   [*] disconnected

The TUI subscribes to the same event types as the web UI. Sequence-based catch-up: the TUI tracks the last event sequence it received and requests missed events on reconnect.

07 // Chat Pane Detail

Streaming, Queuing, Reacting

The chat pane is the core of the TUI. Streaming responses arrive token by token via SSE. Tool calls render inline. A message queue lets the operator stack messages during an active turn with edit/steer/delete controls.

streaming response with tool calls + message queue 
+-- You -----------------------------------------------+
| What's the status on the auth implementation?         |
+-------------------------------------------------------+

+-- Frank (Chief of Staff) --- streaming... --- [3.2s] --+
| Looking at the auth module now...                      |
|                                                        |
|   > read_file(src/auth/handler.go) ... done            |
|   > search_code("validateToken") ... done (3 results)  |
|   > search_code("rateLimiter") ... running             |
|                                                        |
| The JWT validation layer is complete. Session          |
| cookies are in progress on subtask OC-5.2..._          |
+-------------------------------------------------------+
                                            [Esc to cancel]

-- queued -----------------------------------------------
You: "What about the error handling?"       [e]dit [s]teer
You: "Also check the logging setup"         [e]dit [s]teer

Message Types

  • Human messages (labeled "You")
  • Agent messages (streaming)
  • Tool calls (inline, collapsible)
  • System messages (de-emphasized)
  • Interjections (distinct header)

Rich Content

  • Markdown via Glamour
  • Syntax-highlighted code blocks
  • [Image: name.png] references
  • [File: path @ sha] references
  • [Artifact: name (size)] links

Reactions

  • + positive reaction on message
  • - negative reaction + note
  • Shown as [+1] or [-1 "note"]
  • Agent reactions shown subtly

09 // Phase Delivery

Phased Rollout

The TUI is the sole interface for Phases 1 and 2. The web UI arrives in Phase 3 and adds visual richness -- but the TUI continues to be maintained with no features removed.

Phase 1 Synchronous Chat
  • Three-panel layout + dashboard
  • Chat: streaming, @mentions
  • Org session (Frank)
  • Scope indicator (org only)
  • vim keybindings + command palette
  • SSE for realtime streaming
  • CLI: otter send, status, login
Phase 2 Projects + Tasks
  • Task board (text kanban)
  • Task detail with flow stepper
  • Inbox with action keybindings
  • Activity feed (realtime)
  • Agent status + merge queue
  • Scope switching ([ / ])
  • CLI: task, tasks, inbox approve...
Phase 3 Web UI Arrives
  • TUI maintained alongside web UI
  • No features removed from TUI
  • Web adds: flow diagrams
  • Web adds: drag-and-drop
  • Web adds: inline images
  • Web adds: rich media previews
  • TUI remains preferred for terminal users
