Realtime

SSE Event Stream

All live updates via Server-Sent Events. No polling. No WebSocket. Client mutations go through REST. SSE delivers the results back. Unidirectional by design.

Technology

Stack and Design System

Mature tooling chosen for complex interactive UIs. Served as static assets from the OtterCamp API -- no separate frontend deployment. Self-hosters get it automatically.

Framework
React + TypeScript
Component model maps to three-panel layout with independently updating regions. TypeScript enforces type safety across the API contract.
Realtime
Server-Sent Events
Unidirectional server-to-client. Auto-reconnects natively. Works over standard HTTP. No WebSocket complexity.
Deployment
Static SPA Bundle
Embedded in the API service binary. No separate frontend server. Production build ships with OtterCamp distribution.
Rendering
SPA, Not SSR
Behind authentication. No public content or SEO. SPA provides better interactivity for real-time streaming-heavy UI.
Performance
Virtualized + Lazy
Virtualized lists for chat history, run history, activity feeds. Code splitting loads views on demand. SSE event batching prevents UI thrashing.
Libraries
Rich Ecosystem
Diff viewer, syntax highlighting, virtualized lists, markdown rendering, drag-and-drop -- all leveraging React's mature library ecosystem.
Design System -- Color Tokens
Green
Done, success, completed, healthy
Cyan / Blue
In progress, active, normal priority
Amber / Orange
Blocked, warning, high priority
Red
Failed, error, urgent priority
Gray
Pending, queued, cancelled, low priority
Purple
Primary accent, interactive elements, links
Pink
Notifications, unread indicators, badges
Information Density: Power User Design
Dense tables with compact row heights. Minimal whitespace -- every pixel earns its place. Progressive disclosure everywhere: collapsed sections, expandable details, "show more" for large content. No decorative illustrations, hero images, or marketing copy. Every element serves a functional purpose. Dark mode default. Monospace for code and technical content. Proportional font for prose.

Decisions

Resolved Architectural Decisions

18 key decisions locked down in the spec. Each shapes how the web UI behaves and what it deliberately does not do.

1
React + TypeScript SPA. Mature ecosystem, strong tooling for diff viewers, virtualized lists, syntax highlighting.
2
SPA, not SSR. Behind auth, no SEO. Better interactivity for streaming-heavy realtime UI.
3
SSE, not WebSocket. Unidirectional data flow. Client mutations go through REST.
4
Mobile-responsive is sufficient for Phase 3. Dedicated mobile app waits for Phase 4.
5
Dark mode default. Developer audience. Light mode available as toggle.
6
Chat pane always visible. Not a drawer or modal. Persistent panel.
7
No direct object creation. No "new task" buttons. Everything through chat/agents.
8
Sidebar is collapsible. Defaults expanded. Icon-only when collapsed.
9
Chat pane is resizable. Drag left edge. Minimum width enforced. Persisted.
10
Cmd-K is primary keyboard nav. Fuzzy search, quick actions, session switching.
11
Diff view for code review. Incremental review at review nodes. Unified/split toggle.
12
Feature parity with TUI is not a goal. Each client plays to its medium's strengths.
13
Static SPA served by API service. No separate frontend server. Ships with OtterCamp.
14
Notification center is sidebar overlay. Quick access. Not a separate page.
15
Settings viewable, editable through chat. Transparency without inline edit forms.
16
View state in local storage. Session, view, sidebar, chat width, theme persisted.
17
Activity feed is core. Dashboard and project-scoped. Live via SSE.
18
Virtualized rendering. Chat, run history, activity feeds use virtual scrolling.
