Screen Breakdown

Six Screens, One Purpose

Every screen is designed around the 30-second interaction pattern. Get in, get the information, act, get out.

N
Home Screen

Notifications

Primary entry point. Reverse chronological feed grouped by time. Push notifications land here.

  • Urgency indicators with color and icon (not color alone)
  • Grouped by Today, Yesterday, Earlier, Older
  • Tap navigates directly to the relevant item
  • Swipe to dismiss, swipe to open
  • Unread/read visual state; badge count on app icon
  • Critical items pinned to top regardless of scroll
D
Read-Only

Dashboard

Project health at a glance. Answers: "Is everything okay? Does anything need me?"

  • Prominent inbox badge -- the single most important number
  • Project cards with task counts by status
  • Blocked item count highlighted if greater than zero
  • Last activity timestamp per project
  • Quick stats: active tasks, completed today, pending inbox
  • Pull-to-refresh for manual update
I
Read-Write

Inbox

The action-required queue. Every item here blocks progress somewhere.

  • Active and Deferred sections with toggle
  • Inline action buttons: Approve, Reject, Defer, Request Changes
  • Escalations open directly to the relevant chat
  • Work reviews link to web for full diff view
  • Capability approvals with "Approve with Constraints" option
  • Swipe-to-defer for quick triage
C
Read-Write

Chat

Lightweight text sessions. Quick questions and simple instructions to agents.

  • Session list grouped by scope: org, project, task
  • Streaming agent responses with typing indicator
  • @mention autocomplete from session participants
  • Tool calls collapsed to "Agent is working..." indicator
  • No file uploads, no steer, no reactions, no voice
  • Stop button visible during agent turns
T
Read-Only

Task Detail

Full task context when you need to understand what is happening before acting.

  • Status, priority, assignee, and project displayed
  • Compact horizontal flow stepper (scrollable)
  • Subtask summary list with status indicators
  • Collapsible description and acceptance criteria
  • Dependencies: "depends on" and "blocks" links
  • Banner links to inbox if task is awaiting your review
P
Read-Only

Project Status

Drill-down from the dashboard. Full picture of a single project's state.

  • Task counts visualized as a compact status bar
  • Task list sorted by urgency: blocked and review first
  • Merge queue section if entries exist
  • Active schedules with last run and next run
  • Tap any task to navigate to task detail
  • Tap a schedule to see recent task instances
Push Notifications

Four Urgency Tiers

Push notifications are the primary entry point. Only Critical and High push by default. The operator configures the rest.

Critical
Always pushes. Always in-app. Critical items pin to the top of the notification list regardless of scroll.
Escalation reached human, agent failure (unrecoverable), blocker requiring human judgment
Always Push
High
Pushes by default. Always in-app. Standard prominence in the notification list.
Task ready for review, draft pending, @mention in any session, capability approval request
Always Push
Medium
No push by default. Visible in-app. Neutral styling in the notification list.
Task completed, task status changed, agent started work
No Push
Low
No push. Available in feed. Subdued styling. Batched into groups.
Routine status updates, agent activity ("4 tasks updated in OtterCamp V2")
No Push

User Configuration

The operator controls what pushes and when. Configuration syncs between mobile and web.

Per urgency tier
Per project override
Quiet hours (non-critical suppressed)
Per event type (granular)

Deduplication: If the operator has the app open and is viewing the relevant screen, the push is suppressed. The in-app notification is sufficient.

Delivery Infrastructure

iOS: Apple Push Notification Service (APNs)
Android: Firebase Cloud Messaging (FCM)

Deep Link URL Scheme

Every notification includes a deep link. Tap navigates directly to the right screen with no intermediate navigation.

ottercamp://inbox/{inbox_item_id} → Inbox Item
ottercamp://task/{project_slug}/{task_number} → Task Detail
ottercamp://project/{project_slug} → Project Status
ottercamp://chat/{session_id} → Chat Session
ottercamp://notifications → Notification List
ottercamp://dashboard → Dashboard

Universal links (https://app.ottercamp.dev/...) provide web fallback when the app is not installed.

Connectivity

Offline Behavior

The mobile app has limited offline capability. It caches enough state to be useful when connectivity is intermittent, but all actions require the server.

Works Offline

  • Dashboard -- last-known project health, inbox count, task statuses with "Last updated X min ago" indicator
  • Notification history -- recently received notifications cached and viewable
  • Recent chat -- last N messages in recently accessed sessions cached locally

Requires Connection

  • All actions -- approve, reject, defer, send chat, unblock. Server mutations cannot be performed offline
  • Real-time updates -- streaming chat, live notifications, dashboard refresh
  • Uncached items -- navigating to an item not in cache shows a "Connecting..." state
Future consideration: Queued offline actions (approve, send message) submitted when connectivity returns. For the initial release, the app shows a clear "No connection" indicator and disables action buttons when offline. Simplicity over cleverness.
Security

Biometric Authentication

Face ID, Touch ID, fingerprint -- supporting the 30-second pattern. No password typing on every notification response. Session tokens stored in the platform keychain.

1
First login: email and password, same credentials as web UI. Session created.
2
Token stored: session token saved in iOS Keychain or Android Keystore.
3
Subsequent opens: biometric prompt, keychain access, API requests begin.
4
Biometric fails 3x: fallback to password entry.
5
Session expires (30-day sliding window): full re-authentication required.

Sensitive Action Re-confirmation

Certain actions require biometric re-confirmation even when the app is already unlocked:

Capability approvals
Approve with constraints
Org-configured sensitive actions

Standard actions (approve a task review, defer an inbox item, send a chat message) do not require re-confirmation. The initial biometric unlock is sufficient.

Session Management

  • Same auth session as web and TUI -- mobile does not invalidate other sessions
  • 30-day sliding window; active use extends the session
  • Explicit logout revokes the session token
  • Password change from any client revokes all sessions, including mobile
